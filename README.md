# Folinq 页翎

一个在本地运行的 PDF 编辑器。Windows 提供便携版，Android 已开始实现，目前是开发预览阶段。

改几行字、补一张图片、调整几页顺序——这些小事，最好打开文件就能做。页翎想把这条路径做得顺手一点：文档放在自己电脑上，修改后按一下 `Ctrl+S`，继续做手头的事。

项目还在持续开发，已经可以完成一批日常操作。遇到复杂排版时，也有暂时做不到的地方，下面会直接说明。

## 现在能做什么

- **读和整理文档**：多页连续滚动、缩略图跳转、搜索、复制，以及多文档切换。
- **修改内容**：编辑可识别的原生文字，添加文字和图片，拖动位置、调整大小，替换或删除对象。新增图片会自动选中，覆盖区域不会穿透选中下层文字。
- **拖入打开**：将 PDF 拖到首页或编辑区即可打开，支持一次拖入多个文件；也可以把 PDF 拖到 `Folinq.exe` 图标上启动。
- **处理页面**：插入、删除、旋转、调整顺序、合并，以及按页码范围拆分导出。
- **做标记**：高亮、下划线、注释、自由绘画和图形手签。
- **管理文件**：独立 PDF 和项目共用封面网格；项目里可以归组多份文档，最近记录可单独移除，历史版本在编辑页右上角查看和恢复。
- **识别扫描件**：使用 Windows 本机 OCR，复制识别结果，或添加可搜索的文字层。
- **转换与导出**：导出 PDF、PNG、JPG、TXT、Markdown 和 DOCX；也能把图片、TXT、基础 Markdown 和 DOCX 转成 PDF。
- **导出脱敏副本**：框选需要遮住的区域，生成重新栅格化的 PDF 副本。

默认的 PDF 处理和 Windows OCR 在本机完成，OCR 使用系统已安装的识别语言。导出时也可以主动开启在线 PaddleOCR，只有开启后才会上传所选页面。

## 使用便携版

将 Windows x64 便携 ZIP **完整解压**，双击根目录的 `Folinq.exe` 启动。解压后的结构是：

```text
Folinq/
  Folinq.exe
  使用说明.txt
  runtime/           实际应用、DLL、字体、资源与许可证
```

请让 `runtime` 文件夹与启动程序保持在一起。升级时，将新包完整解压到另一个文件夹即可；本机已有的项目、草稿、编辑历史和导出目录偏好会继续保留。文字、图片、注释、绘画和脱敏等操作集中在顶部「编辑」菜单中。窗口较窄时，工具栏自动换行，可通过顶部的「返回项目」「返回编辑」切换页面。

仓库保留源码、构建脚本和应用品牌图标，便携包、测试样本和本地开发文档不随代码提交。

## 版本与开源地址

Windows 程序与工作台使用统一的文件羽毛图标。点击工作台左上角的图标或「Folinq 页翎」，可以打开关于窗口，查看当前版本和构建号。版本信息来自正在运行的程序，本轮便携版为 **0.2.0（构建 2）**。

项目开源地址：[github.com/ShanGuoP/Folinq](https://github.com/ShanGuoP/Folinq)。关于窗口中可以直接访问 GitHub，也可以复制地址；如果浏览器无法打开，地址仍会保留，方便手动访问。

## 最近记录与项目

在 PDF 卡片的菜单中选择「删除记录（保留源文件）」，会从最近文档和项目列表中移除这份 PDF 的记录，重启后仍然生效。源 PDF、本机编辑历史和已有项目归组关系都会保留；删除后可以点击提示中的「撤销」，也可以重新打开 PDF，让记录重新出现。此操作不会清理磁盘上的工作文件。

删除项目分组则会让其中的 PDF 回到独立 PDF 列表，源文件和编辑历史同样保留。

最近记录按更新时间排序，会读取全部合法的工作记录，避免文档积累较多后遗漏新文件。

## 保存和历史

| 操作 | 快捷键 / 入口 |
| --- | --- |
| 打开 PDF | `Ctrl+O` |
| 保存到源文件 | `Ctrl+S` |
| 另存为新文件 | `Ctrl+Shift+S` |
| 放大 / 缩小文档 | `Ctrl+滚轮`（向上放大，向下缩小） |
| 查看、恢复旧版本 | 编辑页右上角「历史版本」 |

保存会先提交尚未应用的文字修改。如果源文件已经被其他程序改过，会提示冲突，避免直接覆盖。

尚未应用的文字输入会随工作记录保存在本机；如果草稿写入失败，会提示重试，并阻止直接关闭导致输入丢失。同一份工作记录同时只允许一个窗口使用：在另一个窗口继续恢复之前，请先关闭原窗口中的文档。程序异常退出后，仍可重新恢复已保存的工作记录。

恢复历史版本后，可以继续编辑，也可以撤销；需要写回原文件时，再按 `Ctrl+S`。导出完成后会显示「导出成功」和保存位置。导出、另存为和脱敏副本共用上次选择的输出目录，重启后仍会记住；首次或该目录已不存在时，默认使用源 PDF 所在文件夹。同名文件自动添加「(1)」「(2)」编号，保留已有文件。

## 关于 Word 和 Markdown 导出

Word 默认使用「保留版式（可编辑）」：把可识别文字转换成 Word 文字，保留字体、字号、粗斜体、颜色和页面位置；识别有边框的表格及合并单元格，保留表头底色、原有图片及图片与文字的覆盖顺序。文字使用定位段落，表格使用原生 Word 单元格，导出文件可以在 Word 中直接修改。

需要大幅修改内容时，可选择「便于编辑（自动排版）」：按阅读顺序重建连续段落、标题、编号列表和原生表格，图片嵌入正文。增加文字后可自动换行和分页，因此页数和原 PDF 可能不同。可勾选「忽略重复页眉页脚」，根据所选的多个页面识别重复内容，包括同行左右分布的页眉页脚和变化的页码；默认保留。

也可以选择「仅提取文字」，便于后续连续排版，不保留原来的图像和定位。扫描页面需要先完成 OCR 并加入可搜索文字层，再转为可编辑 Word；此时识别出来的文字可编辑，识别错误仍需校对。

PDF 只保存最终绘制结果，无法保证恢复原始 Word 的所有语义。复杂多栏、非规则表格、旋转文字、公式和特殊绘图仍需核对；目录目前保留文字外观，不会自动重建 Word 目录字段。修改较长文字时，可能需要调整定位段落或单元格大小。

Markdown 默认选择「结构化 Markdown（推荐）」，识别标题、段落、粗斜体、列表及表格，按阅读顺序输出文字，配图只导出原有图片。普通表格使用 Markdown 表格，合并单元格使用 HTML 表格；可选择忽略重复页眉页脚。图片保存在配套资源文件夹，移动或发送时需要一起带上。「页面图片与版式」仍可生成每页高清图片；「仅提取文字」输出普通文字。以上功能均在本机运行，无需下载额外模型。

## 还在补的部分

PDF 的情况比看上去复杂：扫描件、嵌套对象、特殊字体和多栏排版，并不都能用同一种方法修改。

目前文字编辑主要面向顶层原生文字对象。扫描件上的文字属于图片，OCR 可以帮助搜索和复制，暂时不能直接改掉图片里的字；嵌套 Form 文字和加密 PDF 也还不支持原位编辑。

交互表单、数字证书签名、完整结构化转换和大文件性能还需要继续完善。图形手签只是页面图形。脱敏副本会将整份文档转为图片页面，不保留原来的可选文字、表单或附件。

Android 的首批功能与验证范围见下节；它还没有覆盖 Windows 工作台的全部能力。

## 导出时使用在线 PaddleOCR

电脑和安卓版的 Word、Markdown、TXT 导出窗口提供「在线 OCR · PaddleOCR」开关，默认关闭。对于没有文字层的扫描 PDF，可以直接识别后导出，无需先给原 PDF 添加文字层。

1. 使用 AI Studio 官方服务时，点击「填入官方地址」，使用 `https://paddleocr.aistudio-app.com/api/v2/ocr/jobs`，填写自己的 Token，并填写服务支持的模型名称（默认 `PaddleOCR-VL-1.6`，可手动改成 `PP-StructureV3` 或其他文档解析模型）。软件自动使用 Bearer 鉴权，上传 PDF 后等待异步任务完成。
2. 自部署服务可选择同步文档解析接口，填写完整的 `/layout-parsing` 地址，按服务说明选择 `token` 或 `Bearer` 鉴权；没有鉴权时 Token 可留空。支持 `file`、`fileType` 请求和 `result.layoutParsingResults[].markdown` 返回格式。服务地址和密钥仅留在本次运行内。
3. 选择页面范围后导出。开启开关并点击导出表示同意向所填服务上传这些页面，可能消耗服务额度。每次最多 100 页、25 MB；超出时请分批选择。

官方异步任务提交后会显示任务状态。取消或超时会停止本机等待，云端任务可能继续；同一次运行中，在文档、页码、接口、模型和 Token 未改变时再次导出，会复用已取得的任务编号，避免重复提交。关闭软件后不会保留任务编号。

部分自部署服务默认只处理前 10 页，建议先用 1–10 页试用；超过服务限制时会报缺页并停止保存。需要更多页时，服务端可按官方文档配置 `Serving.extra.max_num_input_imgs`。

Markdown 保存为包含 `document.md` 与配图的 ZIP，各页配图分开放置，避免同名冲突。支持服务返回内联 Base64 图片或 HTTPS 图片地址；下载图片不会携带接口 Token。Word 会把识别结果中的标题、粗体、斜体、编号和项目列表转换为可编辑内容，将 Markdown / HTML 表格转换为 Word 原生表格，支持 HTML 表格的横向与纵向合并单元格，并嵌入返回的 PNG/JPEG 配图。TXT 仍为纯文字。Word 按阅读顺序重新排版，不保证恢复原稿字体、分栏和精确位置，识别结果仍需人工校对。

取消、鉴权失败、超时或返回缺页时不会显示导出成功；不会自动重试付费请求。在线结果只生成副本，保留 PDF 原件、编辑历史与未保存状态。公网服务请使用 HTTPS；使用可信内网的 HTTP 需要手动勾选允许明文传输。Android 手机连接自部署服务时，请填写手机可访问的服务地址，`localhost` 指的是手机自身。

服务部署与协议参考 [PaddleOCR PP-StructureV3 官方文档](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-StructureV3.md)。官方异步接口参考 [AI Studio 文档解析 API 文档](https://ai.baidu.com/ai-doc/AISTUDIO/fml7mozw5)。软件不提供共享密钥，需自行取得服务访问权限。

## Android 开发预览

首批面向 **Android 7.0 及以上、ARM64** 手机，使用独立的移动界面：本机文档列表、底部阅读/编辑/页面/导出入口，以及文字属性弹层。

- 从系统文档选择器导入 PDF，复制到应用私有目录后再编辑，不依赖临时缓存，也不直接修改外部原件。
- 按屏幕宽度连续排列全部页面，单指上下滑动阅读、双指缩放和放大后平移，页码跟随阅读位置。保留上一页/下一页和页面列表跳转；仅加载附近页面，阅读模式不会拖动文字对象。
- 在编辑模式点击文字或图片，再打开属性面板。支持原生文字替换、内置中文字体、缩小字号、高亮及现有对象操作。
- 页面列表支持跳页、旋转当前页和插入空白页，修改可撤销、重做。
- PDF 另存及 PDF、自动排版 Word、TXT、单页 PNG/JPG 导出通过系统文档接口完成；结构化 Markdown 与配图一起导出为 ZIP。写入后校验内容，取消或失败不会显示成功，也不会清除未保存状态。
- 导出的文件可以调用系统分享菜单；前后台切换和返回文档列表时会尝试保存工作状态与草稿。

**安卓版还没有与 Windows 完全对齐。** 当前能力对比如下，未提供入口的功能不能因为共享 Rust 引擎就视为已经移植完成。

| 功能 | Windows | Android 当前预览 |
| --- | --- | --- |
| 连续阅读、缩放、跳页 | 已提供 | 已提供，支持触摸手势与附近页面按需加载 |
| 编辑已有文字 / 图片、撤销重做 | 已提供 | 可点选后在属性面板修改，暂未开放直接拖动对象 |
| 新增文字 / 图片、绘画、手签、脱敏 | 已提供 | 尚未提供完整移动入口 |
| 页面管理 | 插入、删除、旋转、移动、合并 | 跳页、插入空白页、旋转；其余入口待补 |
| 搜索与选字复制 | 已提供 | 移动搜索和字符级长按选字待补 |
| 文档与项目管理 | 多文档、项目分组、历史界面 | 本机文档列表及恢复；完整项目、历史界面待补 |
| OCR | Windows 本机识别与在线导出 | 在线导出；本机识别和文字层入口待补 |
| 导出与另存 | 本地文件导出 | 系统文档选择器另存、导出和分享 |

当前 APK 使用开发签名。已完成 ARM64 构建、签名与 16 KB 原生库/包内对齐检查，并通过移动布局、双指手势及共享引擎的编辑/导出回归测试。连续阅读以 14 页混合横竖版文档验证滑动、缩放、跳页、屏幕尺寸变化和按需加载。**尚未连接安卓真机验收**，系统文件提供者、输入法、分享与进程重启仍需设备测试；本轮没有发布到应用商店。在线协议使用本地模拟服务验证，尚未使用真实付费服务及个人 Token 联调。

在 Windows 开发机安装 Android SDK、NDK **28.2.13676358** 和 JDK 21 后，可运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-android.ps1
```

脚本优先使用 `.tools/android-sdk`、`.tools/java` 和 `.tools/flutter`，也支持通过 `ANDROID_HOME`、`JAVA_HOME` 指定本机环境；会准备字体及固定版本的 PDFium、交叉编译 Rust、构建 APK 并校验包内 ARM64 库。APK 位于 `apps/flutter_app/build/app/outputs/flutter-apk/app-release.apk`。桥接接口有改动时，增加 `-GenerateBridge` 重新生成绑定。

## 本地开发

界面使用 Flutter，PDF 处理和工作会话由 Rust 负责，通过 flutter_rust_bridge 连接。PDF 渲染使用 PDFium。

需要准备：

- Windows x64，以及 Visual Studio 的「使用 C++ 的桌面开发」工具链。
- Flutter 和 Rust。当前开发环境验证过 Flutter 3.47.7 / Dart 3.13.5、Rust 1.99.0。
- `flutter_rust_bridge_codegen` 2.11.1，与仓库锁定版本一致。

```powershell
cargo install flutter_rust_bridge_codegen --version 2.11.1 --locked
powershell -ExecutionPolicy Bypass -File tools/build-windows.ps1
```

生成便携 ZIP 可运行 `python tools/package-windows.py`；已经构建好时使用 `--skip-build`。包的根目录仅保留 `Folinq.exe`、`runtime` 文件夹和使用说明。启动器静态链接自身运行库，实际应用、所需 DLL、资源和许可证集中放在 `runtime` 内；打包脚本检查启动器依赖并校验压缩包中的每个文件。

构建脚本会准备固定版本的 PDFium，并优先使用 `.tools/flutter` 下的 Flutter；也可以使用系统 PATH 中的 Flutter。

仓库保留 Windows 源码、构建脚本和应用品牌图标，本地文档、编译产物和测试资源保持忽略。构建准备脚本会自动下载并校验固定版本的 PDFium、中文字体源文件、字体工具和字体许可证，生成静态中文字体和资源清单，并检查品牌图标是否完整。需要 Python 3.11+，无需全局安装字体工具。字体输出固定时间戳并校验 SHA-256。

Rust 由 `rust-toolchain.toml` 固定为 1.99.0，准备脚本检查 Flutter 3.47.7。本地检查可运行 `tools/check-windows.ps1 -Prepare`，执行资源准备、分析和原生测试；另加 `-LocalUiTests` 可运行本地 Flutter 测试，缺失的测试 PDF 会自动生成。Flutter 测试和视觉基线保留在本机，公开仓库保留原生回归测试和检查脚本。

构建结果位于：

```text
apps/flutter_app/build/windows/x64/runner/Release/Folinq.exe
```

直接运行构建结果时，请保留整个 `Release` 目录及其 DLL、`data` 文件夹。便携打包脚本会将这些运行文件归入 `runtime`，并生成根目录启动程序；两种目录结构对应各自的启动入口。

### 检查代码

```powershell
cargo build --manifest-path rust/Cargo.toml --workspace --locked
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --locked -- -D warnings

cd apps/flutter_app
flutter analyze
```

修改桥接接口后，在仓库根目录重新运行 `flutter_rust_bridge_codegen generate`。

### 目录

```text
apps/flutter_app/       界面、交互和 Windows 宿主
rust/crates/

  app-api/             工作会话、历史、保存及桥接接口

tools/                 构建与环境准备脚本
```
